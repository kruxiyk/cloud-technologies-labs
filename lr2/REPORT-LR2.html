Постановка задачі

Замінити спільний секрет ЛР1 входом окремих користувачів Firebase Authentication; реалізувати модель «власник + модератор», owner_uid з перевіреного токена та Cache-Control: no-store. Використати ті самі Worker і Firestore.

Платформа: Cloudflare Workers; база: Google Firestore; мова: JavaScript.
Адреса після deploy ЛР2: https://lab1-v10-delivery.kruxi-labs.workers.dev
Вхід після deploy: /login
Репозиторій: cloud-technologies-labs, каталог lr2.

Етап 1 Вхід

Провайдери Google і Email/Password; authorized domains localhost і lab1-v10-delivery.kruxi-labs.workers.dev. FirebaseConfig публічний, сервісний ключ та ID token секретні. /login дає вхід, показ uid та виклик API з актуальним токеном. Токен зберігається в пам’яті сторінки.

Додати фактичне підтвердження входу та знімок /login без відкритого токена.

Етап 2 Доступ у API

auth.js адаптовано з наданого прикладу: Firebase accounts:lookup перевіряє токен та користувача, код додатково перевіряє exp, структуру й ідентифікатори проєкту. Роль moderator читається з roles/{uid}; API не дозволяє призначати ролі. Нова посилка отримує owner_uid лише з токена, події успадковують права посилки. Старі посилки ЛР1 без owner_uid бачить тільки модератор.

Для зміни обрано PATCH (у таблиці ЛР1 метод В10 не заданий); owner_uid не змінюється. Статистика ?day враховує лише свої посилки для звичайного користувача; модератор має всі. Додатковий parcel_id перевіряє доступ до статистики конкретної посилки. День, як у ЛР1, визначено за created_on.

Нижче наведено очікувану матрицю для коректних запитів та наявних документів; вона має бути підтверджена результатами check2.mjs.

Висновки

Заповнити після реальних перевірок: окремих користувачів розрізняє uid; автентифікацію відокремлено від авторизації; підміна owner_uid дає 403; сторонній користувач не бачить чужі записи, а модератор має доступ; no-store запобігає повторному використанню персоналізованих відповідей кешем. Фактичні результати: локально [кількість], workers.dev [кількість].

Використання мовної моделі

Codex використано для адаптації коду ЛР1, готових auth.js і check2.mjs, тестів та цього шаблону. Автономні тести перевіряють модель на тестовому сховищі та тестовому Firebase-сервісі, а фактичну роботу Firebase Authentication і публічного Worker необхідно підтвердити окремо.
