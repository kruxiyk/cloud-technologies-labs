1. Мета і постановка задачі

Запустити API ЛР2 як контейнер на Render зі збереженням маршрутів, Firebase Authentication, моделі «власник і модератор» та бази Firestore. Продемонструвати зміну розміру сторінки через серверний Remote Config без нового розгортання та порівняти перший і теплі запити Render і Worker.

Проєкт Firebase: lab1-v10-delivery. Мова: JavaScript. Worker ЛР2: lab1-v10-delivery.kruxi-labs.workers.dev. Репозиторій: cloud-technologies-labs, тека lr3 (перевірити після публікації). Render: вписати фактичну адресу; /login: вписати адресу.

2. Перенесення і локальна перевірка

Код src, сторінку входу та check2.mjs перенесено з ЛР2 без змін. Адаптер викликає той самий app.fetch(request, env); для прив'язки ASSETS реалізовано читання двох файлів public. Маршрут /status повертає 200 без токена й звернення до бази. Додано @hono/node-server і firebase-admin. Перевірка синтаксису успішна, 10 автономних тестів пройшли. Перевірка справжнього API на localhost:8000 завершилася «Пройшло 24 з 24».

Dockerfile з наданого архіву: FROM node:24.21.0-slim задає середовище Node.js; npm ci встановлює production-залежності; USER node запускає процес без root; CMD читає config.env і запускає server.mjs. У спрощеній методичці стовпець образу таблиці не застосовується, тому використано готовий slim. Ключі й паролі виключені .dockerignore. Firestore зберігає дані поза контейнером.

3. Розгортання і перевірка Render

Налаштування: Docker, Root Directory=lr3, Health Check Path=/status, план Free. Секрет передається лише змінною GCP_SA_KEY. Публічна конфігурація Firebase є в config.env. PORT від Render має пріоритет над локальним файлом.

Вставити фактичний рядок журналу з PORT, відповідь перевірки стану та повний вивід check2.mjs за адресою Render.

4. Remote Config без розгортання

Параметр створюється у вкладці Server того самого Firebase. Ключ lr1-api потребує додаткової ролі Firebase Remote Config Viewer. Модуль передає browser з User-Agent і кешує шаблон на 30 с. Умова не є механізмом авторизації. Явний limit запиту має пріоритет над параметром.

Вписати виконані дії: початкові 25 / 8; зміна Edge 8 → 6; час Publish; час останнього Deploy до/після. Зберегти вивід rc.mjs до і після на списку з достатньою кількістю записів.

Вставити results/rc-before.txt і results/rc-after.txt.

5. Холодний старт і порівняння

Для першого запиту Render потрібен фактичний простій 20 хв без звернень. cold.mjs вимірює повний HTTP-запит, після першого робить п'ять теплих запитів і визначає медіану. Значення у мілісекундах перераховуються в секунди. Для Render використовується /status, для Worker — наявний /login; база в цьому порівнянні не вимірюється.

Вставити cold-render.txt і cold-worker.txt; зазначити фактичний період простою.
